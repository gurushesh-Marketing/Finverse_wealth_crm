SHARED LOGIC
Rules that survive every screen. 03
These contracts must be implemented in the service layer and tested across UI, API, export and scheduled jobs.
FINVERSE WEALTH / CRM INTERFACE PROPOSAL / 26 SEP 2026
316
Core lead state machine
Not contacted -> Contacted -> Follow-up -> Pending conversion -> Converted. Contacted may submit Pending conversion
directly if product evidence is complete. Eligible open states may become Lost with reason. Reopen requires approval.
No-answer attempts remain uncontacted. Calls and messages are activities, not pipeline stages. Converted cancellation uses an
adjustment/handoff, not silent stage deletion.
Approval and delegation rules
Default sales conversion reviewer is scoped TL; TL self-submissions go to Manager. Cross-team work transfers route to
Manager, cross-Manager to RM, cross-region to NM, all within permitted scope. Finance decisions require explicit finance
authority. Approvers cannot approve their own requests. Unset limits block approval. Absence uses dated delegation. Timeout
escalates, never auto-approves.
Metric and attribution contract
Store immutable employee, assignment, event time, vertical and hierarchy context. Count unique provider IDs for verified
activity. Recompute rates from summed numerators/denominators; do not average percentages. Cohort conversion uses the
same eligible allocation cohort and observation cutoff. Default win credit locks to the approved closing owner; approved splits
sum to 100%. Cash date and sales credit basis remain separate.

Automatic periods and report
versions
Proposed calendar: Asia/Kolkata, Monday weeks and April-March fiscal year. Support daily, weekly, monthly, quarterly,
half-yearly and yearly reports. Scheduler creates completed-period snapshots after each boundary, proposed 00:15 local time,
with readiness checks and safe retry. Live/MTD views are provisional. Show cutoff, timezone, definition version, source delay
and finance close state. Late corrections produce a revised version.
Four configurable verticals
Wealth, Banking, Markets / Trading and Real Estate remain placeholders until named. Each needs products, hierarchy,
stage/evidence rules, revenue trigger, targets, routing, templates and eligibility. The same-role interface adapts allowed fields
and rules; it never mixes unrelated vertical records. Shared identity matching does not expose restricted opportunities.
Cross-vertical referrals require minimal context, permission and receiving acceptance.
Execution architecture
Browser renders a server-authorised module manifest. API authenticates and authorises each action. Domain service validates
workflow and commits facts plus an outbox event in one transaction. Workers process reminders, imports, providers and PDFs
idempotently. Relational data includes assignments, scopes, opportunities, ownership, activities, tasks, approvals, ledgers and
snapshots. Private files require current download permission.
